# 照见·认知澄清智能体（Zhaojian-Clarify）

一个帮用户梳理关系互动场景、识别潜在关系模式的 AI 辅助分析工具。输入一段对互动的描述，输出：可能存在的关系模式、可直接说出口的应对话术、一句冷却提醒。

个人 MVP 项目，独立完成产品设计、评测体系构建、Prompt 工程、后端、前端与测试评估全流程（AI 辅助开发）。

> **声明**：本仓库为「照见·认知澄清智能体」的公开作品集展示版，提供交互演示、脱敏案例与评测方法说明。演示使用预设结果，不包含完整系统提示词、核心判定规则及私有评测数据，不代表完整可运行版本。

## 交互演示

无需安装与配置，演示地址：https://plainforge7.github.io/zhaojian-clarify/ （或浏览器直接打开 `index.html`）：

- 内置 2 个脱敏示例，点击"示例 1 / 示例 2"即可一键体验完整交互流程；
- 演示覆盖产品的核心交互：关系模式识别卡片、可直接执行的应对话术、冷却提醒、安全关注提示、仲裁介入说明、证据来源查看、本地历史记录；
- 演示结果为预设数据，仅展示产品形态与交互流程，不代表真实模型输出。

## 架构

新旧两版模型输出并行调用，再由规则仲裁：

- **旧版**：直接输出"识别出的模式 / 应对话术"，判断逻辑封装在 System Prompt 内部，是一个不透明的整体判断。
- **新版（V1.1）**：先输出结构化的**证据账本**——把用户描述拆解为若干条，每条标注来源（如"记忆性复述"）、证据状态（如"仅用户报告"）、是否涉及安全关注，再输出条目之间的矛盾清单。
- **仲裁**：以旧版的自然语言结果为主要展示内容；当证据账本中出现"涉及安全关注的条目存在矛盾"这类情况时，仲裁逻辑会介入覆盖旧版结论，改为更谨慎的表述，而不是让模型自己判断要不要谨慎。

两个版本通过线程池并行调用，任一版本失败时有兜底降级路径，不让用户空手而归。

## 测试与评估

维护一套人工评审过的黄金测试用例集，回归测试同时核验安全标记的召回率和仲裁触发的一致性，而不是只看模式识别是否"看起来对"。评测体系覆盖旧版基线 19 条 + 新版候选 20 条黄金用例（用例内容与评测结果属私有数据，不随本仓库公开）；评估结果通过 Dashboard 可视化，包括仲裁覆盖率、安全提示触发次数、逐案例的证据账本明细。

## 未包含的内容

以下内容涉及产品的核心判断逻辑，出于保护考虑未包含在本仓库中：

- 两版 System Prompt 正文（`server.py` 中 `LEGACY_SYSTEM_PROMPT_FILE` 引用的文件，需自行提供同名文件才能跑通）
- 仲裁逻辑模块 `response_arbitration.py`（`server.py` 会 `import` 这个模块，仓库里没有，直接跑会报 `ModuleNotFoundError`，这是有意为之）
- 黄金测试用例集与历次评测结果

也就是说，本仓库展示的是**系统怎么搭**（架构、编排、测试方法论），不展示**具体怎么判断**（Prompt 里的规则细节、仲裁的触发条件与文案）。面试/交流中可以现场演示或讲解这部分。

## Tool Calling 补充项目：`get_history_tool/`

完全独立的小项目，与上面的判断逻辑无关，可以直接跑：给 Agent 一个 `get_history(user_id, topic)` 工具，让它在"当前信息不足"时自主决定要不要调用它去查历史记录，而不是无脑每次都查或者从不查。

- `get_history.py`：Mock 版历史记录查询实现
- `test_cases_get_history.json`：9 个人工设计的测试用例（该调用的、不该调用的、历史为空的）
- `scorer.py`：自动评分器
- `real_agent.py`：接入真实 Claude API 的完整实现
- `get_history_score_report.json`：4 轮真实模型调用的结果，9/9 或 8/9 一致率

运行需要设置 `ANTHROPIC_API_KEY` 环境变量：

```bash
cd get_history_tool
export ANTHROPIC_API_KEY=你的key
python3 real_agent.py
```
